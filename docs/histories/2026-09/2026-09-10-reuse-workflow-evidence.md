## 目标与变更

参考 [OpenAI 延迟优化指南](https://developers.openai.com/api/docs/guides/latency-optimization)，
用户批准减少重复工作和请求往返的方案。复用上一轮独立规划，以 `062df9be` 为初始干净快照实施。

- 明确同任务目标、范围、关键事实和风险假设仍成立时，已完成的独立规划可用于获准实施；
  有影响原结论的变化时进行增量评估，实施授权仍单独判断。
- 相同快照、命令和环境的验证结果可复用，主 Agent 核验实际证据；独立且无共享写入冲突的
  检查可并行。Git index 和交付继续串行，失败或证据缺口仍阻止交付。
- 子代理交接明确待判断问题与必要证据；续办提供变化，没有新问题时简述范围与结论。
- `submit-pr` 在单次拓扑发现中复用已查询的相同仓库信息，忽略大小写；未命中的显式仓库或
  别名仍查询 GitHub。同步说明不跨 plan/apply 调用缓存，不省略写入前后校验。

## 验证

- 新增 3 项行为测试，覆盖显式 `--repo`、大小写差异、`GH_REPO`、显式参数优先级、未知别名，
  以及 plan 后远程默认分支变化时 apply 读取新信息。
- 复用测试先在旧实现下失败：四个参数子场景均多查询一次；修复后同一仓库查询由两次减为一次。
- 全部 26 项 submit-pr 单测及集成测试通过；fixture 使用临时 Git 仓库和模拟 GitHub。
- 6 个 Skill、3 个子代理结构校验、submit-pr quick_validate、Python 编译与 diff 检查通过。
- 独立只读复核无 finding，复用主 Agent 的测试证据，未重复运行相同测试。

## 交付边界

本次不修改子代理模型或配置，不改变双语提交回执、PR 刷新或完整线程处理。主 Agent 精确暂存
并本地提交；未操作真实 PR、push、发布或下游安装。验证证明指定场景减少一次查询，不代表
已测得整体耗时降幅。
