# 执行安全与变更门禁

## 核心规则

- `planning` 只读取、搜索、诊断、起草和报告。
- implementation 必须有明确授权，并且只修改任务允许的路径。
- 保留用户既有 staged、unstaged 与 untracked 改动；不使用 reset、clean 或覆盖式操作清理现场。
- 变更前后执行与风险相称的验证；未运行的验证必须明确说明。
- implementation 产生仓库文件差异时，同步维护本任务的 history。

## 写入前检查

首次写入前确认：目标和允许路径明确、Git 状态能区分用户与 Agent 改动、所需计划/history 已
确定、验证方案可执行。关键授权、范围或产品决策不明确时，暂停依赖它的写入并报告缺口。

## 保护状态

遇到未解决冲突、与用户改动重叠、必要验证失败或无法安全识别交付范围时，保护对应动作。
保护状态不撤销其他已授权的独立检查或修复，也不把 planning 升级为 implementation。
