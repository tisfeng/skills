# 开发规则

## 通用质量

- 修改保持最小、可读且与现有风格一致，不夹带无关重构。
- 按功能和明确职责组织不断增长的区域；解析、I/O、编排和验证混杂时提取同级文件或模块。
- Python、Node 和 Shell 工具优先使用标准库或平台内置能力；新增依赖必须有明确收益。
- 命令行工具的失败信息应说明动作、目标和恢复方式，且不得静默覆盖用户文件。
- 技术标识、命令、路径和品牌名称保留原文；普通说明匹配用户当前请求语言。

## 文档、配置与源码资产

- 文档使用清晰术语和具体行为；避免脱离上下文的抽象限制。链接使用相对路径，重命名后更新活动
  引用而不篡改 completed plan/history 的历史事实。
- 修改 TOML、JSON、YAML 或 Markdown 时，同时验证格式、调用方和受影响文档；不把结构校验当作
  运行时或发布验证。
- `skills/` 的手写源码、脚本和测试保持职责内聚。第三方或生成内容只有在明确标识且具备来源时
  才可整体保留，不得伪装成项目手写实现。
- 修改发布的 Skill 时阅读其 `SKILL.md`。
