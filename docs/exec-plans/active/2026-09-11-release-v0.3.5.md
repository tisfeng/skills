## 工作计划

1. 更新 package 版本，并运行完整发布验证与 `npm pack --dry-run`，冻结候选摘要。
2. 按 `git-commit` 创建发布提交；复验远程基线后 push `main`，等待该完整 SHA 的普通 CI 成功。
3. 再核验占用状态，创建并 push 指向发布提交的 annotated `v0.3.5` tag。
4. 等待 tag workflow 通过，核验 npm、tag、GitHub 默认 Release Notes、包摘要/签名和隔离安装。
5. 回填真实证据，归档计划和 history，提交并 push 记录；不为记录移动公开 tag。

## 风险与恢复

- main CI 失败时不创建 tag；公开 tag 校验失败且需源码修复时使用下一版本。
- npm 状态不明时先查 registry/workflow，不重复 publish；npm 成功而 Release 失败时只续办 Release 阶段。
- npm Trusted Publishing 权限以本次 tag workflow OIDC 成功为准，不以静态配置代替。
