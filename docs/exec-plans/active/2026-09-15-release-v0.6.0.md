## 背景

`v0.5.0` 之后，`git-commit` 增加了可选的全局 `References:` 尾段，并将提交正文改为必须使用
本地化的背景、变更和影响标记。后者会拒绝旧的无标记正文，是对消费方可见的破坏性契约变化，
因此使用新的 minor 版本 `v0.6.0` 发布。

## 目标与范围

- 目标结果：发布 `v0.6.0`，使发布提交、annotated tag、GitHub Release、固定 tag 隔离安装和发布记录可核验一致。
- 允许修改路径：本计划 active/completed 路径与
  `docs/histories/2026-09/2026-09-15-release-v0.6.0.md`。
- 同任务 history：`docs/histories/2026-09/2026-09-15-release-v0.6.0.md`。
- 用户限制：不修改全局配置；隔离验收仅使用临时目录；不移动或覆盖公开 tag；不手写 Release 正文；不发布 npm 包。
- 非目标：不改动候选功能或 release workflow；若发现阻塞缺陷，停止 tag 阶段并以修复后的新候选重新验证。
- 验收标准：发布提交普通 CI 通过；tag peeled SHA、Release 标题和自动生成正文一致；固定 tag 安装只包含 6 个公开 Skills；发布记录已推送且不移动 tag。

## 工作计划

1. 冻结 `v0.5.0..HEAD` 候选，复验远端基线、认证、tag/Release 占用、审查与完整验证矩阵。
2. 创建 Angular-style 发布提交，复验 `origin/main` 未漂移后 push，等待该 SHA 的普通 CI 成功。
3. 重新核验 `v0.6.0` 占用状态，创建并 push 指向发布提交的 annotated tag。
4. 等待 tag workflow 创建 GitHub Release，核验 title、默认 Release Notes、tag peeled SHA 和工作流结果。
5. 在临时消费者从固定 `tisfeng/skills#v0.6.0` 安装，回填证据，归档计划并提交/push 发布记录。

## 风险与决策

- `feat(git)!` 让校验器拒绝旧的无标记三段正文；采用 minor 版本 `v0.6.0`，而非补丁版本。
- 本地 `main` 初始为 `06c7b7b`，比远端 `main` 的 `e95fc40` 超前 3 个提交；将这些已提交变更作为候选发布，不拆分或改写。
- 普通 CI 失败时不创建 tag；公开 tag 校验失败且需要修改源码时使用下一版本；Release 创建失败只恢复 Release 阶段。
- 候选或固定 tag 安装使用临时 npm cache，避免修改用户全局 npm cache。
