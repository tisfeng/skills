1. 审阅完整 `v0.3.8..HEAD` 范围，运行完整验证矩阵并冻结候选内容。
2. 按 `git-commit` 创建发布提交，复验远程基线后 push `main`，等待该 SHA 的普通 CI 成功。

## 风险与决策

- `main` CI 失败时不创建 tag；修复后重新验证并冻结候选。
- 公开 tag 校验失败且需要修改源码时使用下一版本，不移动 tag。
- GitHub Release 创建失败时只恢复 Release 阶段，仍使用精确 tag 标题与 GitHub 默认生成正文。
- 发布完成但隔离安装失败时如实报告，修复使用新版本。
