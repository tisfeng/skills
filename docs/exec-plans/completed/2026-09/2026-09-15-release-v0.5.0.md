# 发布 Skills v0.5.0

- 状态：completed
- 创建日期：2026-09-15
- 负责人：Codex

## 背景

`v0.4.0` 之后，`submit-pr` 改为固定五段式 PR 正文并移除仓库模板合并，又支持在 detached
checkout 中安全创建或复用任务分支。这些对消费方可见的契约调整使用 `v0.5.0` 发布。

## 目标与范围

- 目标结果：发布 `v0.5.0`，使发布提交、annotated tag、GitHub Release、固定 tag 隔离安装和发布记录可核验一致。
- 允许修改路径：本计划 active/completed 路径与
  `docs/histories/2026-09/2026-09-15-release-v0.5.0.md`。
- 同任务 history：`docs/histories/2026-09/2026-09-15-release-v0.5.0.md`。
- 用户限制：不修改全局配置；隔离验收仅使用临时目录；不移动或覆盖公开 tag；不手写 Release 正文；不发布 npm 包。
- 非目标：不改动候选功能或 release workflow；若发现阻塞缺陷，停止 tag 阶段并以修复后的新候选重新验证。
- 验收标准：发布提交普通 CI 通过；tag peeled SHA、Release 标题和自动生成正文一致；固定 tag 安装只包含 6 个公开 Skills；发布记录已推送且不移动 tag。

## 工作计划

1. 冻结 `v0.4.0..HEAD` 候选，复验远端基线、认证、tag/Release 占用、审查与完整验证矩阵。
2. 创建 Angular-style 发布提交，复验 `origin/main` 未漂移后推送，等待该 SHA 的普通 CI 成功。
3. 重新核验 `v0.5.0` 占用状态，创建并 push 指向发布提交的 annotated tag。
4. 等待 tag workflow 创建 GitHub Release，核验 title、默认 Release Notes、tag peeled SHA 和工作流结果。
5. 在临时消费者从固定 `tisfeng/skills#v0.5.0` 安装，回填证据，归档计划并提交/push 发布记录。

## 风险与决策

- `refactor(submit-pr)!` 删除了仓库 PR 模板合并和旧 CLI 正文参数；采用 minor 版本 `v0.5.0`，而非补丁版本。
- 本地 `main` 初始为 `2d3481f`，比 `origin/main` 的 `e76bfaa` 超前 1 个文档提交；将其一并作为候选发布，不拆分或改写已有提交。
- 普通 CI 失败时不创建 tag；公开 tag 校验失败且需要源码修改时使用下一版本；Release 创建失败只恢复 Release 阶段。
