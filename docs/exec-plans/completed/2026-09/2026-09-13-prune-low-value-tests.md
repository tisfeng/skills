## 保留标准

- 至少一个公共成功路径，验证用户可见输出而非私有函数形状。
- 对会覆盖 Git 状态、误写远程、接受漂移证据或丢失分页数据的高风险失败保留直接测试。
- 同一门禁的输入排列使用表驱动或代表性边界，不为每个字段和文案建立独立测试。
- 删除只检查说明文字、测试数据自身或未调用被测逻辑的测试。
- 可移植性测试保留消费者复制、无宿主规则和只读不变式，不重复组件单测的所有字段。

## 风险与决策

- 测试减少不能等同于安全约束减少；保留项按失效后果而非当前代码复杂度选择。
- 行覆盖率不是目标；优先覆盖协议边界、状态不变式和难以人工复现的漂移/分页行为。
- 不为压缩行数改生产代码；测试夹具只在能减少重复且保持可读性时重构。
