## 发布内容

- 新增 tag 触发的 GitHub Actions Trusted Publishing、npm publish 和 GitHub Release 流程。
- `submit-pr` 支持已有 PR 安全快进，并限制唯一、已验证的 GitHub push URL。

- 本地来源携带 `#ref` 时明确拒绝，避免 lock 记录未实际解析的版本。

## 执行步骤

1. 更新 package 版本为 `0.3.1`，创建计划与 history。
2. 运行与 CI 对齐的 Skills、Agents、Python、Node、Shell、测试和 npm tarball 验证。
3. 创建发布提交，复验远程未漂移后 push `main`，等待普通 CI 通过。
4. 重验 npm 版本与远程 tag 未占用，在发布提交创建并 push annotated `v0.3.1`。
5. 等待 tag 的普通 CI 与 Publish npm Package workflow；核验 npm、provenance 和 GitHub Release。
6. 在隔离临时目录验证固定 tag Skills 安装、精确 npm 包 Agent 安装、lock 和 update 幂等性。
7. 归档计划、回填发布证据，创建并 push 最终记录提交。

## 失败恢复

- main CI 失败：不创建 tag，修复并重新验证。
- tag validate 失败且代码需要改变：不移动已公开 tag，改用下一补丁版本。
- OIDC publish 失败且 npm 版本不存在：完成或修正 Trusted Publisher 后只重跑失败任务。
- publish 状态不确定：先查询 registry；版本已存在时不得重跑 publish。
- npm 已发布而 Release 失败：只重跑或补建 Release，不重复 npm publish。
