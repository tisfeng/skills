# PR 功能目标审查

## 目标与授权

用户批准落实 PR 目标理解、Issue 证据采集、需求与实现核对及需求漂移复验方案。
只修改本仓库 Skill 源码、脚本、测试及同任务记录；不操作真实 PR、不 push、不发布或更新全局安装。
复用本任务只读 Planner 的评估，保留完整 diff、线程、Git 权限及默认不等待 CI 的行为。

## 工作计划

1. 新增只读 Issue 上下文采集模块：准确身份、正文、显式讨论分页、来源关系和覆盖状态。
2. 将上下文纳入已有 PR 指纹、collect/refresh、保存快照和手动回退协议，保持 CLI 兼容。
3. 在两个 Skill 间建立目标、验收条件、实现和验证证据的交接；报告功能与代码两类结论。
4. 用针对性行为测试验证采集、失败、漂移和旧快照兼容，并独立审查最终实现。
5. 完成验证、归档计划及 history，按精确范围交付本地提交。

## 风险与验证

- 不把背景引用当作必须解决的需求；无法读取的 Issue 不伪装为空集合。
- 需求变化不依赖 head 变化；旧快照缺少上下文只表示未收集。
- 脚本只收集事实，不通过结构校验替代功能正确性判断。
- 测试覆盖无 Issue、跨仓库引用、分页、失败、正文/讨论漂移、来源移除和旧快照。
- 运行相关 Python 单测、Skill 校验、Python 编译、相对链接检查及 `git diff --check`。
- 功能审查使用隔离的合成证据进行独立演练，不修改真实 PR 或外部服务。
