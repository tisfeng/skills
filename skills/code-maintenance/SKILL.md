# 代码与文档维护

先读项目规则。**默认仅只读检查并给出建议方案**，不修改文件或 Git 状态；仅在用户明确要求修改时按指定范围执行，不顺手改动无关维度（如只改代码时不重排无关文档）。

## 确定范围

用户指定的文件、目录、提交范围、当前改动或全仓优先，注意保留用户已有改动。未指定时，从当前 `HEAD` 选取最近 7 天的提交（最多 50 个），无提交则直接报告无候选：

```bash
git log HEAD --since-as-filter='7 days ago' --max-count=50 --format=%H
```

取选中提交涉及的现行源码与文档路径，并核对已删除文件的引用；历史记录与已完成计划不按现状要求修改。

## 简化与重构代码

选择收益明确、可独立验证的改动；没有明显收益时保持现状。

- **保行为简化**：先读调用方与测试，消除真实重复、过深嵌套与无意义转发，保留公开 API、序列化格式、错误处理、重试与取消等可观察行为。
- **结构重构与职责归位**：拆分过长函数、过重类型或职责混杂的文件，抽取清晰的共享抽象与模块边界；移动或拆分前核对构建目标、模块依赖和资源路径。
- **退役废弃代码**：确认无静态、动态、配置、兼容或工程引用后再删除；无法确认则保留并说明原因。
- **发现疑似缺陷**：不顺手改变可观察行为，报告证据并交由单独修复或 `review` 处理。

涉及对应技术栈时按需读取平台指南：[Swift/Xcode](references/swift-xcode.md)、[Electron/TypeScript](references/electron-typescript.md)。

## 整理 Markdown

聚焦可读性与结构：按主题拆分过密段落、理顺列表层级、修复断链或明显排版问题。保持自然段落，不强行手动折行（项目另有行长约定时遵循项目）。保留原意、frontmatter、表格、代码块和链接完整。

## 核对代码与文档

双向核对候选代码与现行文档中用户依赖的细节（参数、默认值、路径、完整清单等）。只报告有代码或运行证据证实的不一致：已有差异提示用户决定，本轮改动导致的文档过时直接同步。

## 验证与交付

只读检查时输出检查范围、建议方案（附位置与收益）以及已证实的文档差异。执行修改时按项目规则验证受影响入口并交付，报告改动、验证结果（含未验证项）及文档差异的处理状态；即使零改动，也列出已证实的文档差异。
