# 测试保留标准

本仓库只为可观察行为和高风险安全边界维护自动化测试。新增或保留测试时，必须能回答：
“如果实现发生哪一种真实回归，这个测试会失败？”

## 应保留

- 一个代表性的公共成功路径，断言用户可见输出或持久化结果。
- 可能破坏 Git 工作树、索引或引用的状态保护。
- 可能写错 GitHub 仓库、PR、分支或 review thread 的身份与授权门禁。
- 会遗漏远端分页数据、接受漂移证据或把不确定写入报告为成功的完整性检查。
- 复制到无宿主规则的消费者仓库后仍可运行、且保持只读的不变式。

## 不应保留

- 只校验 fixture、JSON 字段或说明文字，却未调用被测逻辑的测试。
- 只固定私有函数调用次数、内部字段排列或诊断文案的测试。
- 与更高层行为测试重复的输入排列；优先保留一个代表性边界或使用表驱动子案例。
- 通过搜索源码证明“没有某条命令”的静态测试；应直接观察 Git 或远端状态是否变化。
- 无法模拟真实 selector 的 Skill description “触发测试”。触发质量由人工或模型评测负责，
 不能用自校验语料冒充自动化验证。

## 评审要求

测试应使用隔离的临时仓库或受控 fake transport，断言失败发生在 mutation 之前，并在需要时
同时检查成功后的最终状态。仅增加覆盖行数、重复现有门禁或锁定实现细节，不构成新增测试的理由。
